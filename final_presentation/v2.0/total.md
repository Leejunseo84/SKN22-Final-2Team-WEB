# 01. 프로젝트 개요: TailTalk (테일톡)

## 1.1 기획 배경 및 문제 정의
* **정보 과잉의 시대**: 국내 반려동물 양육 인구 1,500만 명 시대, 온라인 쇼핑몰에는 수만 개의 상품이 존재하지만 '내 아이'에게 최적인 상품을 찾는 것은 여전히 어렵습니다.
* **검색 피로도 (Search Fatigue)**: 성분 분석, 리뷰 필터링, 가격 비교 등 상품 하나를 고르기 위해 유저가 쏟아야 하는 시간과 노력이 과도합니다.
* **개인화의 부재**: 일반적인 쇼핑몰의 추천은 '인기 상품' 위주이며, 펫의 알러지나 건강 고민을 실시간으로 반영하지 못합니다.

## 1.2 서비스 정의
* **TailTalk**: 사용자와의 자연스러운 대화를 통해 반려동물의 상태를 파탈하고, 최적의 상품을 제안하는 **AI 기반 초개인화 펫 컨시어지 서비스**입니다.

## 1.3 서비스 비전
* **Empowering Pet Parents**: 반려인이 상품 선택의 스트레스에서 벗어나, 반려동물과 함께하는 소중한 시간에 더 집중할 수 있게 돕습니다.
* **Data-Driven Pet Care**: 수집된 데이터를 바탕으로 단순 판매를 넘어 맞춤형 건강 관리로 확장되는 펫 케어 생태계를 지향합니다.

# 02. 사용자 경험(UX) 및 인터페이스 전략

## 2.1 3-Panel 레이아웃 전략
사용자가 정보를 효율적으로 소비할 수 있도록 화면을 세 가지 영역으로 최적화하였습니다.
1. **Left (Chat History)**: 과거 상담 이력을 한눈에 복기하고 세션을 이어갈 수 있는 대화 리스트
2. **Center (Main Chat)**: ChatGPT 스타일의 익숙한 대화형 인터페이스. 끊김 없는 멀티턴 대화 수행
3. **Right (Product Panel)**: 대화 맥락에 따라 실시간으로 업데이트되는 추천 상품 카드 리스트. 클릭 시 상세 페이지로 즉시 연결

## 2.2 하이라이트: 대화형 추천 경험
* **실시간 상호작용**: 유저가 "루이(강아지) 사료 추천해줘"라고 말하면, 우측 패널에 루이의 프로필이 적용된 사료들이 즉각 나열됩니다.
* **프로필 기반 자동 필터링**: 사용자가 별도로 입력하지 않아도 등록된 펫의 알러지 정보를 바탕으로 부적합한 상품은 자동으로 제외되어 노출됩니다.
* **친절한 추천 사유 제시**: "이 상품은 루이가 닭고기 알러지가 있는 점을 고려하여, 양고기를 주성분으로 한 제품으로 골라봤어요"와 같은 구체적인 설명 제공

## 2.3 기술적 구현 (HTML/CSS/JS)
* **프론트엔드 스택**: Django Template 기반의 HTML5, Vanilla CSS3, JavaScript 활용
* **반응성 최적화**: 미디어 쿼리와 플렉스박스(Flexbox)를 활용하여 대화창과 상품 리스트가 조화롭게 배치되는 유연한 디자인 구현
* **동적 업데이트**: Fetch API를 통해 FastAPI와 실시간으로 통신하며 페이지 새로고침 없이 추천 리스트 갱신

# 03. 시스템 아키텍처: 고성능 통합 AI 솔루션

## 3.1 기술 스택 (Tech Stack)
* **Frontend**: Django Templates (HTML/CSS/JavaScript)
* **Services Backend**: Django (User Management, Pet Profiles, Order System)
* **AI Backend**: FastAPI (LangGraph Orchestration, RAG Pipeline)
* **Database**: **PostgreSQL 16** (Unified DB: Relational + Vector Extension)
* **Infra**: Nginx, Docker, Docker Compose

## 3.2 서버 구성 및 데이터 흐름
1. **Request Hub (Nginx)**: 브라우저의 요청을 경로에 따라 Django 또는 FastAPI로 분기
2. **Business Core (Django)**: 사용자 인증, 펫 정보 관리 및 정형화된 데이터의 CRUD 담당
3. **AI Logic (FastAPI)**: 대화 맥락 유지, 하이브리드 검색 수행 및 최적의 답변 생성

## 3.3 아키텍처 혁신 포인트
* **Unified DB Strategy**: 벡터 검색용 외부 DB를 별도로 두지 않고, PostgreSQL의 `pgvector` 확장을 사용하여 RDB와 Vector 데이터를 통합 관리합니다. 
    * **장점**: 데이터 동기화 비용 제로, 인프라 운영 복잡성 최소화, 가용성 증대
* **Micro-Service Pattern**: 사용자 관리와 AI 추천 로직을 서비스 단위로 분리하여 각 도메인에 최적화된 프레임워크(Django/FastAPI) 선택

# 04. 데이터 엔지니어링: 고품질 정밀 데이터 자산화

## 4.1 Medallion 아키텍처 기반 ETL 파이프라인
원시 데이터로부터 추천 품질을 결정짓는 'Gold' 데이터까지의 단계적 가공 프로세스를 구축하였습니다.
* **Bronze (Raw Data)**: 대규모 상품 정보, 상세 정보 이미지, 실사용자 리뷰 데이터 크롤링
* **Silver (Cleaned Data)**: 중복 제거, 결측치 처리, 단위 통일 및 데이터 스키마 정규화
* **Gold (Feature Enriched)**: AI 모델이 바로 활용할 수 있는 심화 정보 결합

## 4.2 데이터 인리치먼트 (Enrichment) 기술
단순한 텍스트 이상의 정보를 추출하여 추천의 근거를 만듭니다.
1. **OCR 성분 분석**: 텍스트가 아닌 이미지로 제공되는 '상품 상세페이지'를 분석하여 주요 성분 및 알러지 유발 물질 목록 자동 추출
2. **리뷰 감성 분석 (Sentiment Analysis)**: 실제 사용자 리뷰 텍스트를 감성 분석하여 상품별 '긍정 지수' 및 '재구매 의사' 스코어링
3. **트렌드 지수 (Popularity Score)**: 판매량, 조회수, 최근 리뷰 빈도를 합산하여 실시간 인기 상품 가중치 산출

## 4.3 하이브리드 인덱싱
* **Full-text Indexing**: 한국어 형태소 분석기(Kiwi 등) 기반의 정밀 키워드 검색 지원
* **Vector Indexing**: OpenAI 임베딩 모델을 활용한 고차원 의미 검색 공간 구축

# 05. AI 엔진: LangGraph 기반 멀티 에이전틱 워크플로우

## 5.1 LangGraph 오케스트레이션
TailTalk의 추천 엔진은 단순한 질문-답변(Linear) 구조가 아닌, 상태(State)와 의도에 따라 동적으로 움직이는 **Agentic Workflow**입니다.
* **Intent Node**: 자연어 분석을 통해 사용자 의도(정보 질의, 상품 추천 등) 분류 및 검색 필터링 매개변수 추출
* **Profile Node**: 선택된 펫의 알러지, 품종, 생애주기 정보를 검색 컨텍스트에 긴밀하게 주입
* **RAG Flow**: 실시간 검색 데이터와 LLM의 지식을 결합하여 정확하고 설득력 있는 개인화 응답 생성

## 5.2 PostgreSQL 통합 하이브리드 검색 (Unified Hybrid Search)
데이터베이스 한 곳에서 모든 검색 요구사항을 처리하는 고효율 엔진을 구축하였습니다.
1. **Semantic Search (pgvector)**: "관절에 좋은 영양제"와 같이 질문의 의미를 파악하는 벡터 유사도 검색
2. **Keyword Search (TSVector)**: "오리젠", "치킨맛" 등 고유 명사와 키워드에 충실한 정밀 검색
3. **RRF (Reciprocal Rank Fusion)**: 벡터 순위와 키워드 순위를 수학적으로 결합하여 검색 결과의 신뢰도를 극대화

## 5.3 지능형 추천 세이프가드 (Safeguards)
* **Allergy Shield**: 펫 프로필의 알러지 성분이 포함된 상품은 추천 목록에서 강제로 제외
* **Age-Aware Filtering**: 퍼피/성견/시니어 등 연령대에 맞지 않는 부적합 사료 필터링
* **Filter Relaxation**: 사용자의 조건이 너무 까다로워 검색 결과가 없을 경우, "브랜드"나 "세부 조건"을 단계적으로 완화하여 최선의 대안 제시

# 06. 신뢰성 검증: 성능 평가 및 품질 분석

## 6.1 신뢰할 수 있는 골든 데이터셋 (Golden Dataset)
추천의 객관성을 확보하기 위해 실제 유저 시나리오를 바탕으로 **100개 이상의 고정밀 테스트 케이스**를 구축하였습니다.
* **데이터셋 구성**: 질문(User Query) + 의도(Intent) + 필터(Filters) + 기대 상품 목록(Expected Goods)

## 6.2 주요 성능 지표 (Performance Metrics)
정량적 평가를 통해 서비스의 완성도를 입증하였습니다.
* **총합 정확도 (Overall Accuracy): 85.2%** ✅ PASS
    * 의도 파악 능력(Logic Precision)과 추천 결과 일치율(Retrieval)의 가중 평균
* **검색 정밀도 (Retrieval F1 Score): 95.7%**
    * 사용자가 원하는 최적의 상품을 검색 결과 리스트에 포함할 확률이 매우 높음
* **키워드 일치성 (Keyword Match): 76.5%**
    * 생성된 답변 내용 안에 펫 이름, 카테고리 등 필수 정보의 포함 여부 측정

## 6.3 정성적 평가 및 분석
* **복합 인텐트 처리**: "루이 사료랑 별이 모래 추천해줘"와 같은 다중 요청 분해 및 처리 능력 검증
* **맥락 유지 능력**: 이전 대화에서 언급된 펫이나 상품 조건을 기억하고 이어지는 질문에 반영하는 일관성 확인
* **필터링의 정확성**: 알러지 성분이 포함된 상품이 단 한 건도 추천되지 않았음을 전수 확인

# TailTalk AI Core Recommendation Logic

TailTalk의 핵심 추천 엔진인 `final_ai`는 사용자의 자연어 입력으로부터 숨겨진 의도를 파악하고, 반려동물의 건강 상태와 취향을 고려하여 최적의 상품을 찾아내는 **Agentic Workflow**를 지향합니다.

## 1. 시스템 아키텍처: LangGraph 기반 오케스트레이션

모든 요청은 **LangGraph**로 정의된 상태 머신을 통과합니다. 이는 선형적인 프로세스가 아니라, 데이터의 상태와 사용자의 의도에 따라 실행 경로가 동적으로 결정되는 구조입니다.

| 노드 (Node) | 역할 |
| :--- | :--- |
| **guardrail** | 부적절한 입력(욕설, 개인정보 등) 차단 |
| **intent** | 사용자 의도 분류 및 상세 필터(브랜드, 예산, 제외 성분) 추출 |
| **profile** | 선택된 펫의 알러지, 건강 고민, 선호 키워드를 검색 맥락에 주입 |
| **query** | 검색 엔진이 이해하기 가장 좋은 형태의 검색 쿼리(Search Query) 최적화 |
| **search** | PostgreSQL(BM25)과 Qdrant(Vector)를 활용한 하이브리드 검색 수행 |
| **rerank** | 검색된 후보군을 사용자의 실제 질문 의도와 펫 적합도에 맞춰 재정렬 |
| **merge** | 서로 다른 도메인(QA, 추천)의 결과를 결합 |
| **respond** | 친절하고 전문적인 말투로 추천 사유와 함께 최종 응답 생성 |

---

## 2. 핵심 기술 엔진 (Core Engines)

### ① 지능형 의도 분류 & 쿼리 분해 (Query Decomposition)
단순한 키워드 매칭이 아닌, 사용자의 복합 문장을 분석합니다.
- **다중 요청 처리**: "우리 집 루이(강아지) 사료랑 별이(고양이) 모래 추천해줘"라는 문장이 들어오면, 이를 두 개의 독립된 태스크로 분해하여 내부 큐(Queue)에 쌓고 순차적으로 처리합니다.
- **카테고리 보정 시스템**: `category.json`에 정의된 별칭(Aliases) 데이터를 기반으로 유저가 "간식"이라고 말해도 내부적으로는 "개껌/져키" 등의 정확한 DB 카테고리로 맵핑합니다.

### ② 맞춤형 검색 세이프가드 (Safeguards)
사용자의 편의뿐만 아니라 반려동물의 안전을 최우선으로 합니다.
- **Allergy Shield**: Kiwi 형태소 분석기를 사용하여 `닭고기`, `치킨`, `계육` 등의 동의어를 통합 관리하고, 펫 프로필에 등록된 알러지 유발 성분이 포함된 상품은 검색 결과에서 강제로 제외합니다.
- **Age-Aware Filtering**: 퍼피용 사료나 시니어용 영양제를 구분합니다. 사료 카테고리의 경우, 펫의 나이대에 맞지 않는 키워드(예: 퍼피인데 '어덜트' 키워드 포함 상품)가 들어간 상품은 필터링됩니다.

### ③ 동적 필터 완화 (Filter Relaxation)
"다이어트 사료"처럼 조건이 까다로워 결과가 적을 때 사용됩니다.
1. **1단계**: 브랜드 조건을 제거하고 검색
2. **2단계**: 상세 카테고리를 상위 카테고리로 확장
3. **4단계**: 건강 고민 태그를 제외하고 범용적인 인기 상품 검색
이러한 단계적 완화를 통해 "결과 없음"이라는 응답 대신, 가장 근접한 대안을 제시합니다.

### ④ 하이브리드 리랭킹 (Hybrid Rerank)
벡터 검색의 유사도와 함께 다음과 같은 생산적 점수를 합산하여 최종 순위를 결정합니다.
- **브랜드 보너스**: 유저가 특정 브랜드를 언급했을 경우 가점 부여
- **품종/건강 고민 매칭**: 펫의 품종별 주의 질환과 상품의 건강 태그가 일치할 때 가점 부여
- **최근성 & 리뷰 감성**: 최신 상품 및 긍정 리뷰 비율이 높은 상품 우선 배치

---

## 3. 데이터 흐름 (Data Flow)

1. **Input**: 유저 메시지 + 세션 기반 대화 이력 + 등록된 펫 프로필
2. **Intent Analysis**: LLM이 JSON 형태로 의도를 정형화 (Pet Name, Brand, Exclusion, Budget 등)
3. **Retrieval**: SQL과 Vector DB에서 각각 후보군(Top 50) 추출
4. **Post-Filtering**: 알러지/나이/제외 성분 중복 체크 및 제거
5. **Final Output**: 추천 사유 + 상품 카드 리스트 생성
